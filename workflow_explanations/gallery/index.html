When a long conversation reaches a page-making request, Main can pass relevant facts, requirements and assets to an isolated production worker. Its repeated production calls can omit unrelated history. Main keeps the conversation and accepts the result. Independent pages or production stages can also be scheduled in parallel when their dependencies allow it.

05Scope and measured overhead

Where the benefits depend on the task.

Workflow is not guaranteed to cost less or finish faster in every run. Cache-hit variation and stochastic LLM behavior can affect cost and time. Finer node splits and more serial handoffs also accumulate startup, binding and coordination overhead. Split work by meaningful responsibilities and dependencies, and parallelize genuinely independent work.

The 0.5.2 example is one page produced in separate fresh gpt-6.1-sol/high conversations with identical supplied facts and code. Skill is a fixed sample; Workflow ran once after engineering checks, using one SDK production worker plus Main routing and acceptance. This pair measures single-page overhead, not the isolation benefit of a long prior conversation.

Where the cost goes

The production worker uses less input than the full Skill run, but Main adds its own context and calls. The cache counts explain this sample's pricing difference; they do not by themselves prove a cache implementation regression.

Where the time goes

There is only one production task here, so production cannot be parallelized across independent pages. The worker alone took longer than the entire Skill sample. The renderer itself took about 1.2 seconds; worker time also includes preparation, model responses, source reads and checks.

Functions and measurement boundary

ER cardinalities, real-code embedding and copy, offline mathematics, and Reply/Remark were checked. Both original template choices are supported: Skill uses doc, Workflow uses sheet. This is a feature check of one pair, not a blind quality score. Costs include the business Main and SDK worker; engineering maintenance and older failed/development attempts are excluded. The tested engine was CAW 1.2 with local terminal-completion fix f05f737; the engine is separate from the Workflow package.

The stronger use case is a page request embedded in a long conversation, where focused production calls can avoid repeatedly carrying unrelated history, or a larger task with independent stages that can overlap. Net gains still depend on the workflow, caching and coordination. Those long-chat gains were not measured by these fresh-conversation pairs.
